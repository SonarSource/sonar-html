Why is this an issue?

Automatically moving keyboard focus to an element as soon as the page loads, before users have had a chance to get their bearings, can disorient or actively harm them:

  • Screen reader users lose the natural reading order: the screen reader jumps straight to the focused element and starts announcing from there, skipping page landmarks, headings, and any content that precedes it.
  • Keyboard and switch-device users cannot navigate to the focused element in a controlled way and may have to navigate backwards through earlier content to understand where they landed.
  • Users who need extra time to process a page, for example due to cognitive impairments, can lose their context when focus jumps unexpectedly, especially if it also triggers a viewport scroll.
  • On touch devices, autofocusing a text input can open the on-screen keyboard unexpectedly and reflow the page.

Autofocusing a dialog element, an element with a popover attribute, an element with an ARIA dialog or alertdialog role, or any element inside one of these, does not raise this issue: moving focus into a freshly opened modal or popover is expected, and the dialog/popover element itself is a valid autofocus target when it should receive focus as soon as it opens.

How to fix it

Remove the attribute that autofocuses the element, and let the browser’s default focus behavior apply. If an element genuinely needs to receive focus in response to a user action, for example a form opened on demand, move it into a dialog element or a popover container instead of autofocusing it directly on page load.

Code examples

Noncompliant code example

<input autofocus />

Compliant solution

<input />

Autofocusing an element inside a dialog or a popover is compliant:

<dialog>
  <input autofocus />
</dialog>

Autofocusing the dialog or popover element itself is also compliant:

<dialog autofocus></dialog>

Autofocusing an element with an ARIA dialog or alertdialog role, or an element inside one, is compliant too:

<div role="dialog" aria-modal="true">
  <input autofocus />
</div>

In Vue templates, an autofocus attribute on a PascalCase or kebab-case tag is not flagged: the analyzer cannot determine how the component renders, so it cannot tell whether the attribute reaches a real DOM element. Note that Vue passes undeclared attributes through to the component’s root element by default, so such code can still autofocus an element:

<CustomInput autofocus />
<custom-input autofocus />
